Same Four-Layer Shape — Different Focus

LAYER 1
Speech-to-Text
Whisper / Dragon / Proprietary
All four products start with ambient ASR. DAX and Abridge use proprietary cloud models; ClinDoc targets Whisper.cpp (Phase 1) — local, no-internet, tunable on Indian accents.
LAYER 2
Entity Extraction
med7 · spaCy · PhraseMatcher
Structured NER pulls symptoms, diagnoses, medications before the LLM sees the text. ClinDoc uses med7 (clinical NER) + rule-based fallback — no hallucinations from the LLM on drug names.
LAYER 3
LLM Structuring
qwen3:30b · Ollama · Pydantic
One prompt per note type, Pydantic schema validation, 1 auto-retry on malformed JSON. The LLM only arranges given facts — it cannot fabricate. Local model means zero API cost and full PHI control.
LAYER 4
Review & Export
contentEditable · FHIR R4
Every field is inline-editable by the physician before export. Edits flow into the FHIR Bundle (Composition + MedicationRequest + Condition) — physician-in-the-loop is a design constraint, not an afterthought.

Why ClinDoc AI for India

🌐
Multilingual by Architecture
Translation normalization layer (stub → Ollama translate → English) sits between ASR and NER. Hindi and Tamil clinical conversations flow through the same pipeline without retraining NER or the LLM prompt.
🔒
Air-Gap Safe
Ollama runs entirely on-premise. No patient data leaves the hospital network — critical for ABDM / DPDPA compliance. Hospitals in Tier-2/3 cities with unreliable internet can still run the full pipeline.
👨‍⚕️
Physician-in-the-Loop
Inline contentEditable on every field — the doctor reads, corrects, then exports. Edits are captured in the FHIR Bundle before any record is finalised. The AI proposes; the physician decides.
💰
Zero Recurring Cost
Fully open-source stack: FastAPI · spaCy · Ollama · React · Vite. No per-seat SaaS fees, no Azure/AWS billing for PHI processing. Deployable on commodity hospital hardware.
📋
Three Note Templates
Consultation (SOAP), Discharge Summary, and Prescription — all three output types named in PS #43. Each has a dedicated Pydantic-validated JSON schema; the LLM never invents field names.
🧬
FHIR R4 Native Export
Exports a standards-compliant Bundle (Patient + Composition + MedicationRequest + Condition) ready for integration with ABDM Health Records or any FHIR-compatible EHR without middleware.
